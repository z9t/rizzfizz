# a-eyes Integration Boundary

Status: active contract boundary.

RizzFizz should not add legacy a-eyes intake files as canonical output.

The current RizzFizz run folder is buildable by a-eyes after a source-safe shim,
but the preferred fix is for a-eyes to accept RizzFizz-native run folders
directly. If a compatibility export is needed later, keep it explicit and
optional rather than making it part of the canonical run surface.

## Do Not Add As Canonical Outputs

```text
brief.raw.txt
brief.structured.json
```

Those are current a-eyes legacy intake requirements. They may be generated by an
a-eyes adapter or a future explicit compatibility export, but they should not be
written by default by `scrub-md`, `import-brief-weaver`, or the sample runners.

## Intended Mapping

```text
variants.json                  -> variant lane packets
build-contract.json            -> shared builder contract
builder-briefs/variant-*.md     -> per-variant builder prompt
preview.html                   -> review / selection artifact
pidge/payload-*-a-eyes.json    -> workbench feed packet candidate
```

## a-eyes Adapter Work

a-eyes should accept a RizzFizz run folder containing:

```text
run-manifest.json
variants.json
build-contract.json
visual-tokens.json
palette-run.json
preview.html
builder-briefs/variant-*.md
optional technology-context.json
optional pidge/payload-*.json
```

The adapter can derive its internal lane packets without raw source material and
without requiring Brief Weaver private files.

## Current Known Delta

The exact RizzFizz sample folder currently fails a-eyes builder intake because
a-eyes still requires `brief.raw.txt` and `brief.structured.json`. A temporary
source-safe shim adding only those files has proven that the RizzFizz data can
drive all variants through deterministic build/eval. The remaining work is
native a-eyes intake support, not adding legacy files to RizzFizz by default.
